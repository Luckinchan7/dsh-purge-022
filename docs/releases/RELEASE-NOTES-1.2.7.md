# dsh-purge-022 v1.2.7

**补丁表 90 → 131 条。新增 41 条容量补丁，并修掉 #19 在真机上其实没生效的问题。**

## 一、这次加的是什么

新增的 41 条（#100–#140）和前面 99 条分工不同：

- **前面 99 条改「行为」** —— 审批门自动放行、身份文本剥离、拒绝重试、请求体形状归一。它们改变宿主遇到某种输入时做什么。
- **这一批改「容量」** —— 宿主出厂把各种输出、检索、并发、超时的预算压得很小，模型一旦真干活就频繁撞顶。每条只动一个常量或一个 schema 默认值，逻辑代码一行不改。

所以这批补丁的风险面很小：没有控制流变化，没有新代码路径，最坏情况是某个上限被抬得比你想的高，而且随时能把值改回去。

## 四、#127 是这次发现的真 bug

`dsh-compaction-tool-result-pruner` 的 Config 写的是：

```js
thresholdChars: z.number().step(1).min(1).default(DEFAULTS.thresholdChars),
```

但 `dsh-base/cordis.patch.yml` 里显式写了：

```yaml
- id: tool-result-pruner
  config:
    thresholdChars: 8192
    headChars: 4096
    tailChars: 1024
```

**显式 config 优先于 schema default。** 所以 #19 把 `DEFAULTS` 从 8192 抬到 16384 之后，运行时读到的仍然是 yml 里的 8192 —— #19 在真机上等于没生效，任何超过 8KB 的工具结果照旧被裁成「头 8KB + 标记 + 尾 1KB」。

这条补丁同时改 yml，`thresholdChars: 50000 / headChars: 32768 / tailChars: 8192`，和 #19 的 DEFAULTS 对齐（#19 的值现在也抬到了这三档）。

## 六、install


## 七、回滚

```powershell
dsh plugin install "<之前的版本>.tgz"
```

每条补丁都走 `*.dshpurge.bak` 备份 + 原子写，回滚不需要手动还原文件。如果只想撤掉某几条，可以在面板里逐条关掉再点应用 —— 关掉的补丁不会还原已改的文件，但下次宿主升级后那份文件会被官方版本覆盖。

## 八、安全边界

#124 / #125 让 `read` 和 `edit` 不再拒绝含 NUL 字节的文件。这是截图里明确要求的（"二进制文件允许 read/edit"），实现方式是：

- read：去掉 NUL 采样拒绝，解码改成 `fatal: false`（非法 UTF-8 变 U+FFFD）
- edit：去掉 NUL 门，同样有损解码

副作用是：读一张 PNG 会得到一堆替换字符而不是报错，改二进制文件可能写出你不想写的内容。这两条是本批里唯一会让你「拿到垃圾数据而不是明确失败」的补丁，如果不需要可以在面板里单独关掉。

其余 39 条都只是把上限调高，不会改变失败语义。
